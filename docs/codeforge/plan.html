実装プラン

コアの技術リスク（サンドボックス実行＋自動採点）をLesson 1本で検証してから、動く土台の上に残りのレッスンを量産する方針で進めた。現在は全9コース47レッスンとユーザー認証まで実装済み。

進行状況

  • 完了 サンドボックス実行 + go test 自動採点のPoC（バックエンドAPI）
  • 完了 Next.jsフロントエンドからAPIを呼び出し、レッスンが一気通貫で動作
  • 完了 スライド形式の解説UI・答えを見る機能・合格ポップアップ・進捗チェックマーク
  • 完了 外部依存（Gin/GORM/SQLite/JWT）を使うレッスン向けの判定イメージ拡張
  • 完了 全5コース27レッスンのコンテンツ、続けてCourse 6〜9（テストの書き方・エラーハンドリング・実践的なアーキテクチャ・デプロイ/Docker化）各5レッスンを追加
  • 完了 ユーザー認証（Cookieセッション）と進捗のサーバー保存
  • 完了 エディタのimportクイックフィックス・コンパイルエラー検知（/check・/format）
  • 完了 CSRF対策・レート制限・採点キューイング、Progate風デザインへの刷新
  • 次 本番デプロイ（新コース追加は完了）

実装時に判明した重要な注意点

採点用ワークスペースの go.mod が go 1.21 指定になっていたため、Go 1.22で追加された http.ServeMux の新ルーティング機能（"GET /path/{id}" のようなメソッド指定パターンやパスパラメータ）が 無効化され、Lesson 2・6のような newMux() を使う問題がすべて404になってしまう不具合があった。 各レッスンの模範解答をローカルで go test 実行して検証する過程で発覚し、internal/judge/judge.go の submissionGoMod を go 1.22 に修正して解消した。詳細は 詳細設計 を参照。

今後の進め方（案）

要件定義に挙げた機能は一通り実装済み。デザインのブラッシュアップ（Progate風のポップな配色・カード）、 CSRF対策・レート制限・採点キューによる同時実行数の制御に加え、「新コース追加」（Course 6〜9）もすべて完了した。 残るは、サービスとして公開するための本番デプロイのみ。

  • クラウド上でのサンドボックス実行基盤選定（Docker Engine直叩き / gVisor / Firecracker等のセキュリティレベル検討）
  • HTTPS化と SECURE_COOKIE=true の適用
  • アプリDBのSQLiteからPostgreSQL等への移行検討
  • Course「デプロイ・Docker化」で学んだ内容（環境変数設定・ヘルスチェック・グレースフルシャットダウン）を、CodeForge自身のバックエンドにも適用する
このドキュメントはCodeForgeの機能追加に合わせて更新されます。
