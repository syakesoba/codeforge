要件定義

Progateのような「ブラウザでスライド解説を読みながらコードを書いて即採点」形式の学習サイトを、一般公開の本格運用サービスとして構築する。

概要・対象

  • 対象言語: Go（他言語経験者を想定し、基礎文法の説明は省略）
  • スコープ: Goの応用分野に特化（Web開発・フレームワーク活用が中心）
    • REST API作成（net/http、Gin/Echoなどのフレームワーク）
    • データベース連携（database/sql、GORMなど）
    • 認証・JWTの実装
    • ゴルーチン・並行処理
  • 対象ユーザー: 一般公開サービスとして本格運用（学習用ポートフォリオではない）

コア機能

  • ブラウザ上でコードを書いて実行・自動採点
  • スライド形式の解説コンテンツ
  • 進捗管理・学習ステータス（レッスン完了記録など）
  • ログイン・ユーザー管理（メール＋パスワード認証）

自動採点方式

Progateのような「標準出力の一致判定」では、REST API・DB・並行処理系の問題を正しく検証できないため、以下を採用した。

  • go test ベースの自動採点を基本方式とする。問題ごとに用意した非公開の _test.go を、ユーザーコードと一緒にサンドボックス内でビルド・実行し、テストの成否で採点する
  • HTTPサーバー系の問題は、実際にポートを開いてサーバープロセスを起動するのではなく、net/http/httptest を使ってテストコード内で完結させる
  • ゴルーチン・並行処理の問題も go test 内で sync.WaitGroup やチャネルの送受信結果を検証する形にし、出力順序に依存しない安定した採点を行う

実装の詳細（Dockerの実行フラグやチューニングの経緯）は 詳細設計 を参照。

DB連携問題の環境

SQLite（インメモリ） を採用する。サンドボックスごとに瞬時に用意でき、外部プロセス（DBサーバー）の管理が不要。本番相当のPostgreSQL/MySQLを扱う発展コースは将来的な拡張として別途検討する。

コンテンツ管理

管理画面は作らず、リポジトリ内に Markdown / Go のソースファイルとしてレッスン・問題をベタ打ちして管理する（problems/ ディレクトリ）。

デザイン方針

Progateに近い、ポップで親しみやすい雰囲気（キャラクター・バッジ等のゲーミフィケーション要素を含む）。現状のフロントエンドはこの方針に向けた土台段階。

マネタイズ

現時点では完全無料。将来の有料化は未検討（設計上は拡張の余地を残す程度に留める）。

Open Questions
