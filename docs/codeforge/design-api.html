API仕様

全エンドポイントのリクエスト/レスポンス形式一覧。

詳細設計トップ 全体構成 採点フロー エディタ・学習体験 認証・進捗 API仕様 フロントエンド構成 セキュリティ
状態変更を伴うエンドポイントはCSRFトークンが必須

POST /api/auth/signup|login|logout、POST /api/problems/{id}/submit、POST /api/problems/{id}/draft は、 csrf_token Cookieの値と一致する X-CSRF-Token ヘッダーが無いと 403 を返す。 トークンは任意のリクエストのレスポンスでCookieとして自動発行される。詳細は セキュリティ ページを参照。

GET /api/problems/{id}

{
  "id": "web-api-basics-01",
  "title": "HTTPサーバーを立てる",
  "markdown": "# Lesson 1: ...",
  "starterCode": "package main\n..."
}

存在しない id の場合は 404。

GET /api/problems/{id}/answer

模範解答コードを返す。「答えを見る」ボタン押下時にフロントエンドから呼ばれる（初期表示のペイロードには含めず、明示的にリクエストされたときだけ返す）。

{ "code": "package main\n..." }

POST /api/problems/{id}/submit

CSRFトークン必須（X-CSRF-Tokenヘッダー）。リクエスト:

{ "code": "package main\n..." }

レスポンス:

{
  "passed": true,
  "output": "=== RUN   TestHelloHandler\n--- PASS: TestHelloHandler (0.00s)\nPASS\nok  \tsubmission\t0.003s",
  "durationMs": 1951
}

タイムアウト時は "passed": false と "error": "timeout" が付与される。

同時採点数が上限（3）に達している間はキューで待機し、待機中にタイムアウトした場合は "error": "queue_timeout" が付与される。

有効なセッションCookieが付いていて合格した場合は、あわせて進捗が記録される。

POST /api/problems/{id}/check

リクエスト:

{ "code": "package main\n..." }

レスポンス:

{
  "diagnostics": [
    { "line": 5, "column": 2, "message": "undefined: fmt" }
  ]
}

go build のみを実行するため隠しテストの内容は漏れない。タイムアウトは8〜10秒。

POST /api/problems/{id}/format

リクエスト:

{ "code": "package main\n..." }

レスポンス:

{ "code": "整形後のコード（不足importを追加・未使用importを削除・gofmt整形済み）" }

構文エラーがあり整形できない場合は 400 でエラーメッセージを返す。

GET /api/problems/{id}/draft

ログイン中ユーザーの自動保存済みコードを返す。未ログインは 401、保存が無ければ 204。

{ "code": "package main\n..." }

POST /api/problems/{id}/draft

CSRFトークン必須。エディタの内容を自動保存する。未ログインは 401。

{ "code": "package main\n..." }

成功時は 204。

POST /api/auth/signup

CSRFトークン必須。1分あたり5回/IPを超えると 429。リクエスト: { "email": "...", "password": "..." }

成功時は 201 で { "id": 1, "email": "..." } を返し、セッションCookieを発行する。

  • 400: メールアドレスの形式が不正、またはパスワードが8文字未満
  • 409: 既に登録済みのメールアドレス

POST /api/auth/login

CSRFトークン必須。1分あたり10回/IPを超えると 429。リクエスト: { "email": "...", "password": "..." }

成功時は 200 で { "id": 1, "email": "..." } を返し、セッションCookieを発行する。失敗は一律 401。

POST /api/auth/logout

CSRFトークン必須。セッションを破棄しCookieを削除する。常に 204。

GET /api/me

ログイン中なら 200 で { "id": 1, "email": "..." }、未ログインなら 401。

GET /api/progress

ログイン中なら 200 で以下を返し、未ログインなら 401。passedAtはストリーク計算に使う合格日時（RFC3339）。

{
  "completedProblemIds": ["concurrency-01", ...],
  "passedAt": { "concurrency-01": "2026-08-08T15:53:19Z", ... }
}

CORS

環境変数 FRONTEND_ORIGIN（デフォルト http://localhost:3000）で許可オリジンを指定。 セッションCookieをクロスオリジンでやり取りするため Access-Control-Allow-Credentials: true を返しており、 フロントエンド側も credentials: "include" を付けてリクエストしている。 Access-Control-Allow-Headers には Content-Type に加え、CSRFトークン用の X-CSRF-Token も許可している。

このドキュメントはCodeForgeの機能追加に合わせて更新されます。
