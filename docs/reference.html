00

使う標準ライブラリ

Go 標準ライブラリだけで完結する部分と、外部ライブラリが必要な部分を分けて把握しておくと迷いません。

ライブラリ使う場所役割
net/http全サービスGin/Echo もこれを基盤にする。ヘルスチェック等で直接使うことも
context全レイヤータイムアウト・キャンセルをハンドラ→ユースケース→DBまで一貫して伝搬
encoding/jsonGatewayREST API のリクエスト / レスポンスの JSON 変換
database/sqlinfrastructure 層MySQL への SQL 発行（ORM 使用時も内部で動く土台）
log/slog全サービス構造化ログ出力（Go 1.21+ 推奨）
os全サービス環境変数の読み込み（DB接続文字列・JWTシークレット）
errors全レイヤーエラーのラップ・判定（errors.Is / errors.As）
sync並行処理部分WaitGroup で goroutine の完了待ち、Mutex でキャッシュを排他制御
time全サービスJWT の有効期限、タイムアウト設定
testing各サービスユニットテスト

標準ライブラリだけでは足りない部分（外部ライブラリ必須）： Web フレームワークは gin-gonic/gin / labstack/echo、 gRPC は google.golang.org/grpc、 JWT は golang-jwt/jwt、 パスワードハッシュは golang.org/x/crypto/bcrypt、 MySQL ドライバは go-sql-driver/mysql、 Redis クライアントは redis/go-redis を使います。

01

用語集

他ページでリンクした用語を、このアプリでの使われ方に絞って独自にまとめました。詳しい仕様が必要になったら、それぞれの公式サイトを別途あたってください。

Gateway / API Gateway設計パターン

本アプリでの役割：外部から受け付ける唯一の入口

複数のサービスへの入口をひとつに集約する設計パターン。クライアントは個々のサービスの場所を意識せず、Gateway が認証チェック・ルーティング・レスポンスの整形をまとめて代行する。

本アプリでは Gin か Echo で実装した Gateway が唯一の外部公開エンドポイントになり、その先の Auth / User / Task サービスへ gRPC で振り分ける。

GinWeb フレームワーク

本アプリでの役割：API Gateway の HTTP ハンドラ実装（候補）

Go 製の軽量・高速な Web フレームワーク。ルーティングやミドルウェアをシンプルな API で扱え、標準の net/http だけで書くより少ないコード量で HTTP サーバーを構築できる。

EchoWeb フレームワーク

本アプリでの役割：API Gateway の HTTP ハンドラ実装（候補）

Gin と並ぶ Go 製の軽量 Web フレームワーク。ミドルウェアの拡張性やエラーハンドリングの書きやすさに定評があり、どちらを選ぶかはチームの好みや既存の設計に合わせて決めればよい。

gRPC通信プロトコル

本アプリでの役割：Gateway と各サービス間の内部通信

Google が開発した RPC（遠隔手続き呼び出し）フレームワーク。通信内容を Protocol Buffers で型定義し、バイナリ形式でやり取りするため JSON+HTTP の REST より高速で、型のズレも起きにくい。具体的な定義は proto設計ページ を参照。

JWT認証トークン

本アプリでの役割：ログイン後の本人確認

JSON Web Token の略。ログイン成功時に Auth Service が発行し、以降のリクエストはこのトークンをヘッダーに付けて本人確認を行う。トークン自体に有効期限と署名が含まれるため、毎回 DB に問い合わせなくても検証できるのが利点。

Protocol Buffersデータ定義言語

本アプリでの役割：gRPC のメッセージ・サービス定義

gRPC で使うデータ定義言語（通称 protobuf）。.proto ファイルにメッセージやサービスの型を書くと、Go・TypeScript など各言語向けのコードを自動生成できる。JSON より転送量が少なく、型の不一致をコンパイル時に検出できる。

Redisキャッシュ / KVS

本アプリでの役割：セッション・頻出データの高速化

メモリ上でデータを保持する高速な Key-Value ストア。ディスクアクセスを伴う DB 問い合わせより圧倒的に速いため、セッション情報やアクセス頻度の高いタスク一覧のキャッシュに使う。

OpenAPI (Swagger)API 仕様フォーマット

本アプリでの役割：Gateway が公開する REST API の仕様書

REST API の仕様を YAML/JSON で記述するための共通フォーマット。エンドポイントやリクエスト・レスポンスの型を定義しておくと、ドキュメントの自動生成やモックサーバー作成、クライアントコードの自動生成に活用できる。

GitHub ActionsCI/CD

本アプリでの役割：テスト・Lint・ビルドの自動化

GitHub に組み込まれた CI/CD 自動化サービス。リポジトリへの push や PR 作成をトリガーに、テスト・Lint・ビルドといったワークフローを自動実行できる。
