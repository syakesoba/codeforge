gRPC · Protocol Buffers

proto ファイル設計
― 各サービスの gRPC インターフェース定義 ―

Auth / User / Task の3サービスが、Gateway や互いとやり取りするための gRPC インターフェースを .proto ファイルとして定義します。実際のコードを書く前に、まずこの契約を固めます。

00

設計方針

3つの proto ファイルすべてに共通するルールです。あとから見て「なぜこう書いたか」が分かるようにしておきます。

→ID はすべて string（UUID 想定）に統一する。オートインクリメントの数値 ID はサービスをまたぐと衝突しやすいため避ける。
→フィールド番号は 1 から順に詰めて割り当てる。将来フィールドを追加するときは末尾に足し、既存の番号は変更・再利用しない。
→enum の 0 番目は必ず _UNSPECIFIED にする（protobuf は未設定時に自動で 0 を使うため、0 に意味を持たせないルール）。
→一覧取得は page_size / page_token によるカーソル方式のページネーションを採用する。
→Auth Service は「認証」に専念し、ユーザー情報そのものは持たない。ユーザーデータの保持・更新は User Service の責務にして重複させない。

01

auth.proto

ログイン・新規登録・トークン検証の3つだけを扱う、意図的に小さいサービス。

proto/auth/auth.protoAuth Service

syntax = "proto3";

package auth;

option go_package = "example.com/go-study/gen/auth";

// Auth Service: ログイン・登録・トークン検証を担当する
service AuthService {
  rpc Register(RegisterRequest) returns (RegisterResponse);
  rpc Login(LoginRequest) returns (LoginResponse);
  rpc ValidateToken(ValidateTokenRequest) returns (ValidateTokenResponse);
}

message RegisterRequest {
  string email    = 1;
  string password = 2;
  string name     = 3;
}

message RegisterResponse {
  string user_id = 1;
}

message LoginRequest {
  string email    = 1;
  string password = 2;
}

message LoginResponse {
  string access_token = 1;
  int64  expires_at   = 2; // Unix time（秒）
}

message ValidateTokenRequest {
  string access_token = 1;
}

message ValidateTokenResponse {
  bool   valid   = 1;
  string user_id = 2; // valid=true の場合のみ有効
}
RPCRequestResponse説明
RegisterRegisterRequestRegisterResponse新規ユーザーを登録する。実際のユーザーレコード作成は User Service の CreateUser に委譲する
LoginLoginRequestLoginResponseメール・パスワードを検証し、成功したら JWT を発行する
ValidateTokenValidateTokenRequestValidateTokenResponseGateway が受け取ったトークンの有効性を検証する（署名・期限チェック）

02

user.proto

ユーザー情報そのものの CRUD。Auth Service の Register 完了後や、Task Service からの参照で呼ばれる。

proto/user/user.protoUser Service

syntax = "proto3";

package user;

option go_package = "example.com/go-study/gen/user";

// User Service: ユーザー情報の CRUD を担当する
service UserService {
  rpc CreateUser(CreateUserRequest) returns (User);
  rpc GetUser(GetUserRequest) returns (User);
  rpc UpdateUser(UpdateUserRequest) returns (User);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse);
}

message User {
  string id         = 1;
  string email      = 2;
  string name       = 3;
  int64  created_at = 4;
}

message CreateUserRequest {
  string email         = 1;
  string password_hash = 2; // 平文は送らない（Auth Service 側でハッシュ化済み）
  string name           = 3;
}

message GetUserRequest {
  string id = 1;
}

message UpdateUserRequest {
  string id   = 1;
  string name = 2;
}

message DeleteUserRequest {
  string id = 1;
}

message DeleteUserResponse {
  bool success = 1;
}
RPCRequestResponse説明
CreateUserCreateUserRequestUserAuth Service の Register 完了後に呼ばれ、ユーザーレコードを作成する
GetUserGetUserRequestUserGateway や Task Service がユーザー情報を参照する際に使う
UpdateUserUpdateUserRequestUserプロフィール更新
DeleteUserDeleteUserRequestDeleteUserResponse退会処理

03

task.proto

3サービスの中で唯一 enum と一覧取得（ページネーション）を持つ、いちばん実装量の多いサービス。

proto/task/task.protoTask Service

syntax = "proto3";

package task;

option go_package = "example.com/go-study/gen/task";

// Task Service: タスクの CRUD を担当する
service TaskService {
  rpc CreateTask(CreateTaskRequest) returns (Task);
  rpc GetTask(GetTaskRequest) returns (Task);
  rpc ListTasks(ListTasksRequest) returns (ListTasksResponse);
  rpc UpdateTask(UpdateTaskRequest) returns (Task);
  rpc DeleteTask(DeleteTaskRequest) returns (DeleteTaskResponse);
}

enum TaskStatus {
  TASK_STATUS_UNSPECIFIED = 0; // protobuf の規約でゼロ値は必ず _UNSPECIFIED にする
  TODO        = 1;
  IN_PROGRESS = 2;
  DONE        = 3;
}

message Task {
  string     id          = 1;
  string     user_id     = 2;
  string     title       = 3;
  string     description = 4;
  TaskStatus status      = 5;
  int64      created_at  = 6;
  int64      updated_at  = 7;
}

message CreateTaskRequest {
  string user_id     = 1;
  string title       = 2;
  string description = 3;
}

message GetTaskRequest {
  string id = 1;
}

message ListTasksRequest {
  string user_id    = 1;
  int32  page_size  = 2;
  string page_token = 3; // 2ページ目以降は前回の next_page_token を渡す
}

message ListTasksResponse {
  repeated Task tasks           = 1;
  string        next_page_token = 2; // 空文字なら最終ページ
}

message UpdateTaskRequest {
  string     id          = 1;
  string     title       = 2;
  string     description = 3;
  TaskStatus status      = 4;
}

message DeleteTaskRequest {
  string id = 1;
}

message DeleteTaskResponse {
  bool success = 1;
}
RPCRequestResponse説明
CreateTaskCreateTaskRequestTaskタスクを新規作成する
GetTaskGetTaskRequestTask単一タスクを取得する
ListTasksListTasksRequestListTasksResponseユーザーのタスク一覧をページング付きで取得する
UpdateTaskUpdateTaskRequestTaskタイトル・説明・ステータスを更新する
DeleteTaskDeleteTaskRequestDeleteTaskResponseタスクを削除する

04

コード生成

proto/ に置いた定義から、protoc で gen/ 配下に Go のコードを生成します。生成物は手で編集せず、常に proto ファイルの方を直します。

事前準備（初回のみ）：

go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest

生成コマンド：

protoc \
  --go_out=gen --go_opt=paths=source_relative \
  --go-grpc_out=gen --go-grpc_opt=paths=source_relative \
  proto/auth/auth.proto proto/user/user.proto proto/task/task.proto

毎回手打ちしなくて済むよう、Makefile に make proto のようなターゲットとしてまとめておくと扱いやすくなります。生成された *_grpc.pb.go の XxxServiceServer インターフェースを実装するのが、実装ガイドの「⑤ gRPC Server」 にあたります。
