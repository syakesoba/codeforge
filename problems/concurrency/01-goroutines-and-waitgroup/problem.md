# Lesson 1: ゴルーチンとWaitGroup

## 今回学ぶこと

- `go` 文で処理を並行実行する方法
- `sync.WaitGroup` で複数のゴルーチンの完了を待つ方法
- Go 1.22で変わった「forループの変数」の扱い

## 解説

### ゴルーチンとは

関数呼び出しの前に `go` を付けるだけで、その関数は**ゴルーチン**という軽量スレッドの中で並行に実行されます。呼び出し元は結果を待たずに次の行へ進みます。

```go
func sayHello() {
	fmt.Println("Hello from goroutine")
}

func main() {
	go sayHello()
	// ここで sayHello() の完了を待っていないので、
	// 何も表示されないまま main が終了することがある
}
```

上のコードは、`main` 関数が `sayHello` の実行を待たずに終了してしまう可能性があるため、期待通りに動かないことがよくあります。ゴルーチンを使うときは、**完了を待つ仕組み**とセットで使うのが基本です。

### sync.WaitGroupで待つ

`sync.WaitGroup` は「あといくつのゴルーチンが終わっていないか」を数えるカウンターです。

- `wg.Add(1)`: 待つべきゴルーチンを1つ増やす
- `wg.Done()`: ゴルーチンが1つ終わったことを知らせる（`defer wg.Done()` と書くのが定石）
- `wg.Wait()`: カウンターが0になるまでブロックする

```go
func doubleAll(nums []int) []int {
	result := make([]int, len(nums))

	var wg sync.WaitGroup
	for i, n := range nums {
		wg.Add(1)
		go func() {
			defer wg.Done()
			result[i] = n * 2
		}()
	}
	wg.Wait()

	return result
}
```

それぞれのゴルーチンは配列の**異なるインデックス** `result[i]` にしか書き込まないため、同時に実行しても衝突しません（同じ場所に複数のゴルーチンが書き込む場合はLesson 3で学ぶ `sync.Mutex` が必要になります）。

### Go 1.22でのforループ変数の変更

Go 1.21以前は、`for i, n := range nums` の `i` と `n` はループ全体で使い回される**同じ変数**でした。そのため、ゴルーチンの中でそのまま使うと、ゴルーチンが実際に実行される頃には `i`/`n` の値が書き換わってしまっている、という有名なバグがありました（対策として `go func(i, n int) { ... }(i, n)` のように値をコピーして渡す必要がありました）。

Go 1.22からは、`for` ループの各回で `i`/`n` が**新しい変数**として扱われるようになったため、上記のコードのように余計な引数渡しをしなくても安全に書けます。CodeForgeの採点環境はGo 1.22以降なので、このレッスン以降は素直にループ変数をそのままゴルーチンの中で使って構いません。

## 演習

`doubleAll` と同じ考え方で、`squareAll` 関数を実装してください。`nums` の各要素を**2乗**した結果を返す関数です。ゴルーチンと `sync.WaitGroup` を使い、各要素の計算を並行に行ってください。

## ヒント

- 戻り値用のスライスは `make([]int, len(nums))` で先に用意しておくと、各ゴルーチンがインデックスを指定して書き込めます
- `wg.Add(1)` → `go func() { defer wg.Done(); ... }()` → ループの外で `wg.Wait()` という型を意識してください
